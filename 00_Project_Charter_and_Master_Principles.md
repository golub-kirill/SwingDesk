## 1. Что такое SwingDesk

SwingDesk **не является**:

- обычным учебником;
- библиотекой индикаторов;
- подборкой торговых советов;
- одним большим playbook;
- одним универсальным торговым алгоритмом;
- LLM, свободно смотрящей на график и принимающей решения;
- системой, оптимизирующей параметры ради красивого backtest.

SwingDesk **является**:

> **Формализованной, версионируемой, проверяемой и объяснимой предметной моделью свинг-трейдинга, на основании которой можно построить исследовательскую платформу, backtest engine, risk engine, portfolio engine и ограниченного автономного AI-агента.**

Уроки свинг-трейдинга выступают источником терминов, концепций, гипотез, техник, стратегий, ограничений, сценариев, рисков и описаний рыночного поведения. Но **утверждение из урока не становится автоматически исполняемым или доказанным.**

Каждое утверждение проходит преобразование:

```text
Course Statement
    → Classified Concept
    → Formal Definition
    → Rule / Event / State / Hypothesis
    → Machine-Readable Specification
    → Implementation
    → Validation
    → Approved Runtime Object
```

Ни один этап не пропускается. Наличие техники в уроке **не означает**, что она должна быть сразу включена в реальную торговлю.

## 2. Модель качества

Нормативная модель (инженерная, не буквальная формула):

```text
System Quality ≈
    Real Edge
  × Data Integrity
  × Research Discipline
  × Validation Quality
  × Risk Control
  × Execution Realism
  × Operational Discipline
  × Monitoring
  × Governance
```

Ключевое следствие произведения: **если один множитель близок к нулю, вся система ненадёжна.** В частности, `Real Edge = 0` обнуляет всё остальное, каким бы чистым оно ни было.

Из этого — фундаментальные обязательства документации. Она ОБЯЗАНА прямо фиксировать:

- чистые данные не превращают отрицательное ожидание в положительное;
- дисциплина не спасает стратегию без edge;
- хороший backtest не доказывает будущую прибыльность;
- высокий win rate не является достаточным показателем;
- даже подтверждённый edge может быть уничтожен плохим исполнением;
- даже прибыльная стратегия может дать неприемлемую просадку при плохом risk management;
- стратегия может потерять edge после изменения рынка;
- система ОБЯЗАНА уметь отказаться от решения и остановить торговлю.

Формальный порядок работы вытекает отсюда напрямую: **сначала установить, что первый множитель не ноль** (реальный edge на out-of-sample), и лишь затем разворачивать полноту документации вокруг доказанного ядра. Полнота структуры не является заменой доказательству edge.

## 3. Главная директива

Финальная система строится так:

```text
Уроки
  → Формальная база знаний
  → Canonical Machine-Readable Specification
  → Data + Feature + Event + State Engines
  → Independent Strategy Candidates
  → Validated Expectations
  → Bounded AI Decision Agent
  → Independent Risk and Portfolio Gate
  → Execution and Order Management
  → Broker
  → Outcome and Audit
  → Offline Validation and Knowledge Update
```

Ключевой принцип, обязательный к соблюдению во всех документах и всех объектах:

> **AI выбирает лучшее допустимое действие, но не получает права изменять факты, придумывать вероятность, обходить риск, менять параметры или самостоятельно расширять область полномочий.**

Система НЕ ДОЛЖНА иметь возможности:

- выдавать предположение за факт;
- выдавать урок/книгу за доказательство;
- выдавать backtest за гарантию;
- выдавать LLM confidence за вероятность;
- выдавать неизвестное (`UNKNOWN`) за отрицательный результат (`FALSE`);
- продолжать торговлю после выхода за validated domain;
- отправлять ордер при нарушении risk policy.

## 4. Отношение к TradAlert (негативный референс)

TradAlert — предшествующая торговая система, построенная по внешне схожей философии (чистые функции, YAML-конфиг, типизированные слои, валидационные методы). Она служит SwingDesk **негативным референсом**: источником не структуры, а перечня конкретных режимов отказа, которые SwingDesk ОБЯЗАН исключить архитектурно.

Урок TradAlert формулируется одной фразой:

> **Все обнаруженные дефекты были дефектами факта или проводки, а не дефектами логики; аудиты логики их не ловили, потому что искали в единственном месте, где дефектов не было.**

Из post-mortem TradAlert выведены шесть сквозных требований (см. `01_Normative_Requirements_and_Conventions.md`, раздел «Сквозные требования»): отсутствие константного гейта; тождество backtest/live; point-in-time календарь без литералов дат; провенанс каждого числа в выводе; validation stage требует реально исполнившегося прогона; отсутствие «тёмного» выключателя риск-контроля. Эти требования встроены в SwingDesk **с самого начала**, а не добавляются аудитом позже. Причина именно в этом: находка, оставшаяся прозой в документе, ничего не блокирует; блокирует только исполняемая проверка, привязанная к нормативному требованию.

## 5. Режим работы

- **Основной язык документации:** русский. **Технические идентификаторы и canonical terms:** английский.
- **Формат:** Markdown, YAML, JSON Schema, Mermaid, CSV где уместно. Git-friendly, diff-friendly, без скрытых бинарных источников истины. PDF допустим для генерации, но **не является** canonical source.
- **Режим этой фазы:** документация. Минимум кода. Продукты фазы — спецификации, схемы, каталоги, онтология, реестры. Исполняемые харнессы и фетчеры описываются как требования с `verification_method`, но не реализуются на этой фазе.
- **Статус уроков:** источник (уроки свинг-трейдинга) находится в разработке и неполон. Доменное извлечение (конкретные rules, strategies, features, значения параметров) ОТЛОЖЕНО до готовности полных версий уроков. Каркас онтологии и требований строится «вперёд», с явными `UNSET` на местах, куда встанет доменный материал. Отсутствующий параметр корректно остаётся `UNSET`; работа над структурой из-за этого не останавливается.

## 6. Нормативная сила этого документа

Устав задаёт рамку, внутри которой существуют остальные документы комплекта. При конфликте между этим уставом и любым нижестоящим документом по вопросу мастер-принципов приоритет имеет устав. Изменение мастер-принципа порождает новую версию устава с записью в `change_log` и не производится молча.
