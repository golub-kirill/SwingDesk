# 10 — Реестр параметров и калибровка

```yaml
document_metadata:
  document_id: DOC-PARAM-010
  title: Реестр параметров и калибровка SwingDesk
  version: 1.0.0
  status: DRAFT
  owner: null
  reviewers: []
  source_documents: [master_specification/v1.0, tradalert_postmortem/TRADALERT_REVIEW]
  dependency_documents: [DOC-ONTOLOGY-003, DOC-REQ-001, DOC-RULE-011]
  requirement_refs: [REQ-RISK-001, REQ-EVIDENCE-001]
  unresolved_issue_refs: [UDR-001]
  created_at: null
  updated_at: null
```

**Все параметры находятся в едином реестре.** Порог НЕ ДОЛЖЕН быть спрятан в тексте, в коде, в UI, в локальной конфигурации или внутри имени стратегии. Форма source-independent: конкретные значения приходят из уроков и калибровки (`UDR-001`); здесь определяется, как параметр описывается, как выбирается и когда блокирует runtime.

Форма несёт два урока TradAlert напрямую:

- **86 непрослеженных «ручек».** Реестр требует у каждого параметра назначение, категорию источника, потребителей и признак блокировки runtime. Параметр, который ничего не меняет, обнаруживается переписью (sensitivity), а не живёт как место, где будущий читатель думает, что принимается решение.
- **«Выключено ради baseline».** Реестр + `REQ-RISK-001` требуют, чтобы выключенный риск-контроль нёс датированную ADR со сроком; просрочка роняет сборку. `UNSET` (параметр ещё не задан) и «тёмный выключатель» (контроль задан, но мёртв) — разные состояния, и форма различает их.

---

## 1. Категории источника параметра

Категория определяет, **как параметр вправе получать значение**. Смешение категорий — источник переоптимизации.

| Категория | Значение и правило |
| --- | --- |
| `DEFINITION_FIXED` | Определяет сам объект. Не оптимизируется без создания другого объекта. |
| `MARKET_CONVENTION_SEED` | Общепринятое стартовое значение. **Не считается оптимальным.** |
| `BOOK_OR_PRACTITIONER_SEED` | Значение из книги/практики. Является гипотезой или prior, **не** доказанным оптимумом. |
| `EMPIRICAL_THRESHOLD` | Определяется по данным (калибруется). |
| `ADAPTIVE_PARAMETER` | Зависит от инструмента, режима, percentile, volatility, rolling distribution. |
| `RISK_POLICY` | Определяется владельцем капитала и risk mandate, **не** максимизацией backtest. |
| `PORTFOLIO_POLICY` | Как `RISK_POLICY`, на уровне портфеля. |
| `EXECUTION_CONSTRAINT` | Из модели исполнения. |
| `BROKER_CONSTRAINT` | Из внешнего ограничения брокера; версионируется по времени. |
| `REGULATORY_CONSTRAINT` | Из регуляторного ограничения; версионируется по времени. |

Критично: значение из книги — это `BOOK_OR_PRACTITIONER_SEED`, то есть **prior**, а не истина. Мастер-ТЗ прямо запрещает «выдавать книжные значения за доказанно оптимальные».

## 2. Статусы параметра

```text
UNSET        — не задан; описан, но значения нет
CANDIDATE    — предложен диапазон/значение
SEEDED       — задано стартовое (seed) значение
CALIBRATING  — идёт калибровка
PROVISIONAL  — предварительно выбрано, не финализировано
VALIDATED    — подтверждено на out-of-sample/walk-forward
LOCKED       — зафиксировано для runtime
MONITORED    — в проде под наблюдением дрейфа
DEPRECATED   — выведено
REJECTED     — отклонено
```

`VALIDATED` недопустим без ссылки на validation record (`REQ-EVIDENCE-001`).

---

## 3. `UNSET` — допустимое состояние с обязательным описанием

Параметр МОЖЕТ оставаться `UNSET`, пока не завершена описательная модель. Работа над структурой из-за `UNSET` не останавливается. Но каждый `UNSET` **обязан** нести полное описание:

- тип; назначение; единицу; допустимую область;
- предполагаемый источник; candidate range; метод калибровки;
- критерии принятия; зависимости; область применения;
- влияние на систему; **блокирует ли он runtime**.

`UNSET` без этих полей недопустим — это скрытый пробел, а не честно зафиксированный.

## 5. Правила выбора значения

**Запрещено** выбирать значение: по максимальной in-sample прибыли; только по win rate; по одному тикеру; по одному периоду; по одному режиму; **по test set**; по точечному максимуму; без costs; без slippage; без sensitivity-анализа; с ложной точностью; после многократного просмотра holdout; без учёта числа испытанных вариантов.

**Предпочтение:** устойчивым плато; широким рабочим диапазонам; нормализованным параметрам; ATR-based расстояниям; percentiles; volatility-adjusted порогам; простым решениям; минимальному числу степеней свободы; параметрам с экономическим объяснением; hierarchical defaults вместо подгонки каждого тикера.

**Ложная точность запрещена.** Значение `2.5` с обоснованием на выборке из 20 наблюдений при σ(R)≈1.2 даёт стандартную ошибку среднего ≈0.27R — то есть оценка неотличима от шума. Порог «минимальной выборки, на которую можно опираться» (`minimum_sample_size`) обязан выводиться из расчёта мощности, а не назначаться круглым числом.

> В TradAlert порог доверия к статистической ячейке был выставлен на `n=20`, где оценка +0.08R имеет t≈0.3. Форма требует, чтобы `minimum_sample_size` имел статистическое основание.

## 6. Parameter Budget (бюджет параметров)

Для каждой стратегии фиксируется: число свободных параметров; число перебранных комбинаций; обоснование каждого параметра; допустимая сложность; предпочтение простейшей устойчивой модели. Бюджет параметров — вход в контроль multiple testing (`21`, `26`): чем больше перебрано вариантов, тем строже поправка на множественность и тем выше требуемая значимость.

---

## 7. Разграничение `UNSET` и «тёмного выключателя» (`REQ-RISK-001`)

Два разных состояния, которые форма обязана различать:

| Состояние | Что это | Требование |
| --- | --- | --- |
| `UNSET` | Параметр ещё не имеет значения | Полное описание (раздел 3); `runtime_blocking` определён |
| Dark switch | Контроль **задан и корректен**, но выключен (`enabled: false`) | Датированная ADR с `owner`, `reason`, `review_by`; просрочка → сборка падает |

Второе состояние не описывается через `UNSET` — параметр задан, он мёртв. Любой риск-контроль в `enabled: false` обязан нести ADR со сроком пересмотра. Это превращает молчаливое, бессрочное выключение в явное, ограниченное во времени решение.

> В TradAlert так были выключены шесть готовых, корректных контролей, четыре — с обоснованием «ради неизменности baseline». Один из них (anti-chase veto) при включении убирал 20.6% всех входов. Форма не позволяет такому выключателю жить без срока годности.

---

## 8. Инварианты формы (проверяются статически)

- каждый параметр имеет `category`, `purpose`, `unit`, `allowed_domain`, `consumers`, `runtime_blocking`;
- `UNSET`-параметр несёт все обязательные описательные поля (раздел 3);
- `runtime_blocking: true` при `status: UNSET` блокирует переход владельца (правила/стратегии) в runtime;
- `instrument_override_allowed` по умолчанию `false` (запрет подгонки под тикер);
- `BOOK_OR_PRACTITIONER_SEED` не может иметь `status: VALIDATED` без собственного validation record (это prior, не доказательство);
- `minimum_sample_size` не пуст для калибруемого параметра и имеет обоснование мощностью;
- параметр без единственного `consumer` помечается как кандидат на удаление (перепись мёртвых ручек).
